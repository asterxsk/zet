Using

Keybindings

Eighteen actions are bound by default. A binding is a chord — modifiers and a key — and it lives in the [keys] table of config.toml.

The default bindings

Action, default chord, and what it does
ActionDefaultWhat it does
new-tabCtrl+Shift+TOpens a tab at the current grid size.
close-tabCtrl+Shift+WCloses the active tab. Closing the last one quits.
next-tabCtrl+TabActivates the next tab by number.
previous-tabCtrl+Shift+TabActivates the previous tab by number.
new-windowCtrl+Shift+NStarts a second process, rather than a second window in the same process. Tabs belong to a window, so two windows would otherwise share one tab list.
copyCtrl+Shift+CCopies the selection to the clipboard. Does nothing when there is no selection.
pasteCtrl+Shift+VWrites the clipboard to the active terminal, bracketed when the program asked for bracketed paste.
findCtrl+Shift+FOpens the find bar over the bottom of the grid and gives it the keyboard. While it is open, typing goes into the query rather than to the shell.
settingsCtrl+Shift+CommaOpens the settings panel over the right edge of the grid. The terminal stays live behind it.
toggle-tab-positionCtrl+Shift+PFlips the tab strip between the top row and the left rail. This is the one action that changes the configuration in memory.
scroll-page-upShift+PageUpScrolls back one page.
scroll-page-downShift+PageDownScrolls forward one page.
scroll-to-topCtrl+Shift+HomeScrolls to the oldest line.
scroll-to-bottomCtrl+Shift+EndReturns to the live grid.
font-largerCtrl+PlusOne point larger, capped at 72.
font-smallerCtrl+MinusOne point smaller, floored at 4.
font-resetCtrl+0Back to the configured size.

The eighteen names in that table are exactly the actions zet knows. A [keys] entry naming anything else is a diagnostic, not a silent no-op.

Writing a chord

  • Modifiers are Ctrl, Shift, Alt, and Super, in any order and any case, joined to each other and to the key by +. The key comes last.
  • Ctrl+Shift+T, ctrl+shift+t, and Shift+Ctrl+T are the same chord as far as the modifiers go.
  • Case does not imply Shift. Shift is written out. A chord is compared exactly, including the case of a character, so Ctrl+Shift+T names a capital T. A binding written with the wrong case never fires, which is a better failure than one that fires on a keystroke you did not describe.
  • The + key itself is written Ctrl++. Everything before the last token that is not a modifier is taken as the key, so splitting on every + would break it.
  • Function keys are F1 through F24. F0 and F25 are not keys.
  • A misspelled modifier is reported as an unknown key, because at that position the two are the same mistake: Foo+T and Ctrl+NotAKey are both a typo somewhere.

Named keys

A single character names itself. Everything else uses one of these names, and the list is matched without regard to case.

Key names accepted in a chord
GroupNames
Charactersa–z, A–Z, 0–9, and any single character, including @ and +
EditingEnter, Tab, Backspace, Escape, Space, Delete, Insert
NavigationHome, End, PageUp, PageDown, Up, Down, Left, Right
FunctionF1 … F24
Lock and systemCapsLock, NumLock, ScrollLock, PrintScreen, Pause, Menu
PunctuationPlus, Minus, Comma, Period, Slash, Semicolon, Quote, Backquote, Backslash, BracketLeft, BracketRight, Equal

A chord written with a punctuation name matches under shift whatever the layout puts above that key: Ctrl+Shift+Comma is what to write, and it fires whether your layout produces < there or something else. Writing the shifted character instead — Ctrl+Shift+< — is the same chord on a US layout and a different one everywhere else, so the name is the one to prefer. Letters are the exception and are matched exactly: Ctrl+Shift+T and Ctrl+Shift+t are two different chords, and only one of them is bound.

Rebinding

The action name is the key and the chord is the value. Rebinding an action replaces its default; you do not have to repeat the bindings you are keeping.

[keys]
new-tab = "Ctrl+T"
close-tab = "Ctrl+W"
quit = "Ctrl+Shift+Q"

The full default [keys] table is on Configuration, and it is a complete list: a key you omit keeps the default above rather than becoming unbound.

Unbinding an action is therefore written rather than left out. An empty chord is an action with no key:

[keys]
close-tab = ""

close-tab now answers to nothing, and stays that way across a restart. The settings panel writes this line itself when you capture a chord that another action already had, which is the one case where it takes a binding away from something you did not ask about.

What a chord is not

  • There are no sequences and no prefix keys. A chord is one key with modifiers, and a binding either matches a keystroke or it does not.
  • Zet's own bindings are asked first, before the key is encoded — and that holds even for a program that has negotiated the kitty keyboard protocol. The protocol changes what the terminal sends; it does not say the terminal stops having a keyboard of its own, and a terminal that gave its shortcuts up the moment a program asked for all keys would be one where the settings panel could be unreachable from inside whichever full-screen program happened to be running. A program that wants one of these chords for itself needs the user to unbind it, which the settings panel has a row for.
  • The clipboard is plain CF_UNICODETEXT in both directions. There is no rich text and no image paste.
