Using

Configuration

zet reads one TOML file at %APPDATA%\zet\config.toml. A key that is missing takes its default. A key that is not in the schema is an error.

Two writers, one file

The settings panel (Ctrl+Shift+Comma) edits this file in place as you change rows in it, so a setting moved there is a line changed here. The save is a merge against what is already on disk rather than a rewrite: a value you did not change comes out as you wrote it, and so does the comment beside it. What it does not keep is a key the schema does not have — a save writes the shape a load accepts, and a key that is not in the schema is an error, so the file is told about it rather than quietly tidied.

The file

Three rules shape the schema, and they are worth knowing before you edit anything.

  • Every key has a default. A key that is present and equal to its default is indistinguishable from one that is absent. That is what lets a hand-editor delete lines without breaking anything.
  • A key that is not in the schema is an error, not a shrug. Silently ignoring fonnt.size means you change a setting, see nothing happen, and have no way to find out why. The cost is that a config written by a newer zet is rejected by an older one, which is the right trade here.
  • A bad file never stops the app from starting. A terminal that refuses to open because a colour is misspelled is a terminal you cannot use to fix the misspelling.

Colours

A colour is a string carrying an sRGB hex value: "#0a0b0d". The # is required, and the three channels are two hex digits each.

Themes

Eight themes ship. Three are zet's own and are held to a 4.5:1 contrast floor on their body-text colours. Five are imported from their authors and ship unmodified so they look like themselves. The three zet themes come first in the picker, and the imported ones follow in the order below.

Background

The window's background is a tagged table. kind says which of the three it is, and the fields that follow belong to that kind.

It covers the whole window. The chrome paints its own surfaces over it, and the grid leaves its ground unpainted, so what shows through the terminal is the background. A cell a program gave a background to still paints it: a gradient is the window's, not the program's.

# The theme's ground colour, flat. This is the default.
[window.background]
kind = "solid"

# A picture, scaled to fill. `opacity` is the picture's own; the theme's ground
# shows through below it.
[window.background]
kind = "image"
path = "D:/Images/grid.png"
opacity = 0.85

# A two-stop linear gradient. The angle is degrees clockwise from pointing right.
[window.background]
kind = "gradient"
from = "#0a0b0d"
to = "#1a1030"
angle = 45.0

Diagnostics

Values that parse but cannot be used are reported separately from values that do not parse at all. size = -3 is a perfectly good float and a perfectly bad font size. Each such value is replaced by its default, and the app runs on it.

CheckSeverityWhat the app runs on

cursor.thickness outside 1 to 8warningThe value clamped to the range.

A file that is not valid TOML at all gets one diagnostic naming the line, and the app runs on defaults. Trying to salvage individual sections out of text the parser rejected would mean guessing which part of the file you meant, and guessing wrong is worse than saying so.

A worked example

A configuration that changes the theme, raises the font size, puts the tab strip on the left, makes the cursor a two-pixel bar that does not blink, and rebinds two actions. Nothing here is required: any line omitted takes its default.

# zet — my settings
theme = "gruvbox-dark"

[font]
family = "Cascadia Mono"
size = 16.0

[window]
opacity = 0.95
remember-position = true

[window.background]
kind = "gradient"
from = "#0a0b0d"
to = "#151a24"
angle = 90.0

[tabs]
position = "left"

[cursor]
shape = "bar"
blink = false
thickness = 2

[appearance]
text-scale = 0.0
follow-reduce-motion = true

[keys]
# Rebinding an action replaces the default. The action names are the keys.
new-tab = "Ctrl+T"
close-tab = "Ctrl+W"
quit = "Ctrl+Shift+Q"

Only the keys you write are changed. font.fallback, tabs.open-default-without-asking, appearance.follow-forced-colors, and every binding not listed above keep their defaults.

The update check

There is no setting for this, and no [update] section to put one in. zet makes no request on its own — not on launch, not on a timer, not in the background — so the whole of the feature is two flags:

zet --check-update
zet --update

The first asks GitHub whether a newer version has been published and prints the answer; it downloads nothing and changes nothing on disk. The second does the same check and then installs what it finds — download, digest check, replace the running binary — with the new version taking effect the next time zet starts.

Neither reads your configuration, which also means both work on a machine whose config will not parse — exactly when someone might want them. An earlier draft reserved an [update] check-on-launch key for an automatic check on launch; it was removed before the first release, so no completed version of zet has ever opened a socket because it was started. Privacy states the request in full.
